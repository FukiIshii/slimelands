# slimelands ゲームデザイン文書 (GDD)

## コンセプト
Stacklands(カード積み重ね式の村運営)と「ゆっくり育てていってね」(半自動ダンジョン戦闘)を組み合わせた、スライム育成×村運営×ダンジョン攻略ゲーム。
人間ではなくスライムが村人となり、合成・配合・ガチャで様々な種類のスライムを生み出し、パーティーを組んでダンジョンに挑む。

## ゲームループ

```
村パート
├─ 合成(カード重ね) → 基本種スライム
├─ 配合(既存スライム + 素材) → 上位種スライム
│   └─ 異なるタイプ同士 / 同じタイプ同士、どちらの組み合わせも存在し、結果が変わる
├─ ガチャ(召喚) → 全種類が排出対象(確率は種類ごとに異なる)
├─ 制作 → 武器・防具・アクセサリー(ダンジョン産の素材が必要)
└─ 育成 → レベルアップ(マナクリスタルを消費)、進化(ダンジョン産の素材が必要)

    ↓ パーティーを編成してダンジョンへ出発

ダンジョンパート
├─ 複数種類のダンジョンが存在("ゆっくり育てていってね"踏襲)
├─ ダンジョンごとに必要な体数・出現する敵(既存のSlimeSpeciesDataを流用)が設定されている
├─ マップ移動は簡略化し、ウェーブ単位で敵と自動的に遭遇する
│   ├─ 1ウェーブに複数体の敵が同時出現することがある
│   └─ ウェーブの出現条件は「時間待ち」「前ウェーブ全滅直後に即座」の2種類
├─ 戦闘は半自動進行。プレイヤーが操作するのは以下のみ:
│   ├─ 必殺技の発動タイミング(クールタイム制)
│   └─ 攻撃対象(ターゲット)の指定(タップで固定、対象が倒れると自動照準に戻る)
├─ タイプ相性が戦闘のダメージ計算に影響する(下記「タイプ相性」参照)
├─ パーティー全員が気絶した時点でダンジョン失敗(途中離脱・撤退はなし)
└─ ダンジョン内の敵を全て倒せばクリアで素材がドロップ
    (クリア時、敵の見た目は消えるがプレイヤー側のスライムは村に戻るまで画面に残り続ける。
    失敗時=パーティー全滅時は敵味方とも見た目が消える)

    ↓ 素材を持ち帰る

村パートへ還元(ループ)
```

## スライムの入手方法

| 方法 | 役割 |
|---|---|
| 合成(カード重ね) | 基本種の入手 |
| 配合(既存スライム+素材) | 上位種の入手。属性の組み合わせで結果が変化 |
| ガチャ(召喚) | 全種類が対象。レア度により排出確率が異なる |

## スライムのステータス

- **才能値・個体値**のような隠しパラメータを持ち、同じ種類でも個体差が出る
- **スキル**は複数持てるが、数を絞ってシンプルさを保つ(詳細な上限数は今後調整)

## スライムの見た目・移動・攻撃タイプ

- 移動はアニメーションコスト削減のため、飛び跳ね(バウンド)移動を採用する
  (そもそもスライムをプレイヤーキャラクターに選んだ理由の一つでもある)
- 攻撃タイプは近接/遠距離の2種類があり、シルエット(見た目の形状)で視覚的に区別する
  - **近接タイプ**: 「The スライム」的な、定番の高弾力シルエット。飛び跳ねて移動する
  - **遠距離タイプ**: さまざまな球体シルエット。転がって移動する
  - 形状の対比(高弾力=接地感・安定 / 球体=浮遊感・不安定)だけで攻撃タイプを判別できるようにするデザイン方針
- 頭上に種族アイコン等を表示する演出は「没個性になりかねない」ためNGとした
- 常に動き続けている(バウンド/転がる)キャラクターのため、待機モーション(アイドルアニメーション)は用意しない方針
- 戦闘中、プレイヤー・敵とも背景画像の下半分(床の部分)の帯の範囲内を自由に動き回る
  (一箇所に固定されない、奥の壁・天井側にははみ出さない)。
  移動中もバウンド/転がる移動アニメーションはそのまま重ねて再生される
- 敵は行動帯の中に即座に出現するのではなく、画面外(右または左)から歩いて登場する演出を挟む。
  どちら側から登場するかは製作者がInspectorから設定できる
- 攻撃対象となる敵が1体もいない間(遭遇待ち等)、プレイヤー側スライムは行動帯全体ではなく
  中央付近の狭いエリアだけを徘徊し、なるべく中央周辺に留まり続ける(エリアの幅はInspectorで
  調整可能な仮値)。敵側の徘徊や、交戦中(敵がいる間)の接近・後退の移動には影響しない
- ダンジョン専用画面の背景は、戦闘状態(遭遇待ち/戦闘中)に関わらず常にスクロールし続け、
  パーティーが右方向へ進んでいく感覚を演出する(背景タイルは右から出現し左へ抜けていく)。
  ダンジョンごとに絵柄を差し替えられる

## 攻撃・必殺技の仕様

- 基本攻撃(通常攻撃)は「突進(近接タイプ)」または「スライム弾(遠距離タイプ)」の2種類
  - 武器は見た目の装飾要素であり、基本攻撃の方式自体はスライムの種族(攻撃タイプ)に紐づいて固定される
- 近接タイプの通常攻撃は、対象が射程(一定距離)より遠い場合はその場で攻撃せず、対象へ向かって
  接近し続ける。射程内に入った瞬間に初めて攻撃が発動する(徘徊中に対象との距離が開けば、
  再び射程外になり攻撃を止めて接近を再開する)
  - 必殺技はプレイヤーが任意のタイミングで発動できる特別な行動のため、この接近待ちの対象外
    (発動時点で対象が射程外だと、通常攻撃と同様に接近が間に合わず命中しない=ダメージ0のミスになる)
- 敵(攻撃対象)がいる間、近接タイプは対象へ接近し、遠距離タイプは逆に対象から離れる(距離を
  取り続ける)。この交戦中の移動速度は、通常の徘徊時の移動速度とは別にInspectorで調整できる
  (交戦中は徘徊時より素早く動けるようにする想定)
- 攻撃発動(接近/発射モーション開始)から実際のダメージ反映までは一定の遅延を挟み、見た目の
  接近モーションが対象に届くタイミングと同期させる。遠距離タイプは対象との距離に関わらず命中する
  (弾が届くまでの飛行時間はあるが、ミスの概念はない)
- 必殺技はパズルゲーム「ぷよぷよ」の必殺技システムを参考に設計する:
  - 必殺技の候補プールは近接系/遠距離系で完全に分離する(混在しない)
  - 同じプール内では、複数のスライム種族が同じ必殺技候補を共有できる(使い回し可)
  - 各スライム種族が持てる必殺技候補は種族ごとに**固定**
  - 個体ごとの必殺技は、進化・レベルアップのタイミングで候補の中から抽選され、以後その個体では固定される
  - ※現状の実装(`SlimeIndividual.LearnSkill`)は候補プールからの抽選ではなく個別学習の形になっており、
    「候補プールから抽選して固定」の仕組みは未実装(下記「今後詰める論点」参照)
- 必殺技はスキルごとに命中範囲の形状を持てる(単体対象/円形/直線/左右スイープ)。円形・直線・
  スイープはPhysics2D(トリガーコライダー+`Physics2D.OverlapCircleAll`/`OverlapBoxAll`)を使い、
  各ユニットが持つ検出専用コライダー(見た目に依存する当たり判定用、ダメージ計算は持たない)に
  実際に触れたかどうかで命中を判定する。プレイヤー側/敵側で別々の物理レイヤーに分け、
  必殺技が味方を誤って巻き込まないようにしている
  - 円形: 対象の座標を中心とした円の範囲内にいる敵全員にダメージ
  - 直線: 発動者から対象方向へ伸びる直線状(矩形)の範囲内にいる敵全員にダメージ
  - 左右スイープ: 行動帯の左端〜右端を往復し続け、接触している間ダメージを与え続ける
    (ダメージを与える頻度は個別に調整可能)
  - 近接タイプの通常攻撃・単体対象必殺技の射程判定(接近待ち/命中ミス)も、同じ検出専用コライダー
    (`Physics2D.OverlapCircleAll`)を使った当たり判定に統一されている。攻撃者の座標を中心とした
    射程円の範囲を検出し、対象の当たり判定コライダーに実際に重なっているかで命中を判定するため、
    ユニットの当たり判定サイズ(コライダー半径)の分だけ、単純な中心点同士の距離比較より
    わずかに射程が広がる(体格を持つもの同士が触れ合えば届く、という自然な判定になる)
  - 範囲・持続時間・ダメージ頻度などはスキルごとにInspectorで調整可能な仮値(具体的な必殺技の
    パターン数・中身は下記「今後詰める論点」の対象のまま、今回実装したのは仕組みのみ)

## タイプ相性(戦闘への影響、確定仕様)

- 火は草に強い/草は水に強い/水は火に強い(三すくみ)
- 光と闇はお互いに強い(双方向)
- 無属性はどのタイプとも相性なし
- 有利な attacker → defender の場合、ダメージに+20%(仮値、要調整)の補正がかかる。
  不利な側の減算は今回は設定していない(有利側のみの片方向ボーナス)
- 実装は`TypeAffinityData`(ScriptableObject)で、attacker/defenderの組み合わせと倍率をInspector上で編集できる

## 配合・合成レシピの発見の仕組み

- レシピは**確定制**(同じ素材の組み合わせなら必ず同じ結果が生まれる。既存の`CardRecipeData`の設計方針と一致)
- レシピ自体はプレイヤーに公開せず、試行錯誤によって発見してもらう
- 発見の手助けとして、素材に視覚的・分類的なヒントを持たせ、「それっぽい組み合わせ」に見えるようデザインする
- 使用する素材は2種類以上
- レシピにない組み合わせを試した場合は不成立(何も起こらず、ただ重なっているだけのスタックになる。既存実装の挙動と一致)
- 発見したレシピは図鑑形式で記録される(※図鑑UIは未実装)

## リソース

| リソース | 入手方法 | 用途 |
|---|---|---|
| 資源(木材など) | 採掘・伐採などの生産活動 | スライムの食料(生のまま与えても良いが、料理すると食料値の回復量が大きい) |
| マナクリスタル | 村施設(マナだまり)で時間経過により生成(確定仕様。ダンジョン産素材への一本化の対象外) | ガチャのコスト消費、レベルアップに使用 |
| ダンジョン産素材 | ダンジョンクリア報酬。マナクリスタルを除く、配合・進化・制作に使う素材は今後これに一本化する方針(下記「ダンジョン解放・進行システム」参照) | 配合・進化・武器防具アクセサリーの制作に使用 |

## ダンジョン解放・進行システム

- 配合・進化・制作に使う「ダンジョン産素材」の入手手段は**ダンジョンのみ**に一本化する
  (村側の資源循環を一方通行にすることで、詰み・進行阻害を防ぐ意図)
  - ただし**マナクリスタルはこの一本化の対象外**とし、引き続き村施設(マナだまり)での
    時間経過生成のままでよい(確定仕様)
- ダンジョンは周回可能
- ダンジョンの解放はツリー構造で表現する:
  - 親ダンジョンをクリアすると、紐づく子ダンジョンが解放される
  - 1つの親ダンジョンから2〜3個の子ダンジョンに分岐する
  - 複数の親ダンジョンのクリアを条件とする合流ノードも存在する
  - ダンジョンツリーは他の画面とは別の専用画面に表示し、右側へ伸びていく形にする

> **実装との差分メモ**: 「ファイアクリスタル」は現状生成手段が未実装のまま進化レシピの素材として
> 使われている。素材入手をダンジョンに一本化する方針(マナクリスタルを除く)に合わせて、
> ダンジョンドロップとして実装するかどうかは別途要検討(下記「今後詰める論点」参照)。

## リスク・ゲームオーバー要素

- **ダンジョンでの気絶**: スライムは死なず気絶のみ。HPが回復するまで次のダンジョンに参加不可。経験値やステータスへの恒久的なペナルティはなし
- **村の食料切れ**: Stacklands同様、村の月齢が経過するタイミングで食料が尽きると村がゲームオーバーになる
- **神殿**: 気絶したスライムを復活させられる施設
